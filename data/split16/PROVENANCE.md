# split16 role-map provenance

`role-map.json` is generated by `tools/migrate_split16.py`, not captured or
derived from any native output. For each of the 65 split16 stage freeze
files (`glassbox_nr/kernels/split16_rXX/freeze/*.json`, one per B23-B30/
B40-B47 stage), it records the package-local path and sha256 of the four
roles `glassbox_nr/node_executor.py`'s `load_split16_stage()` actually
reads (`map_wiring`, `map_npz`, `contraction`, `weights`) -- the freeze
files themselves still record the *original* project-relative paths, which
don't exist in this package; this file is the resolver's lookup table
instead.

16 of the 65 `contraction` entries carry two shas instead of one
(`source_sha256` plus `sha256`) because those particular contraction files
were published as derived copies (stripped of disassembly-derived
diagnostic content -- see `data/maps/PROVENANCE.md`'s "split16 stage maps"
section and `release/_private/DERIVED_FILES_MAP.json` for the exact rule).
`source_sha256` is checked against the (unedited) freeze index's own
recorded value; `sha256` is checked against the derived bytes actually on
disk. The other 49 entries are byte copies and carry only `sha256`.

`data/split16/not-packaged-roles.json` (informational-only freeze-index
roles this loader never reads -- predictor/comparator/driver/arith/
mapexec2/etc., plus per-sample `input:*` role names) is kept internally in
`release/_private/vit_derivation_manifests/split16-not-packaged-roles.json`
rather than published here, since it is a build record, not runtime data.
