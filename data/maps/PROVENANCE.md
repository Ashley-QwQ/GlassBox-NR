## B39 map data

`b39-map.json` + `b39-map.npz` (used by `glassbox_nr/kernels/b39/predict_b39.py`
and `glassbox_nr/node_executor.py`'s B39 branch). The npz is a byte copy. The
json is **derived** (2a sweep, 2026-09-15): the original's `interp` subtree
carried a PTX instruction mnemonic census and `backward_branches_taken`
($L__BB labels) -- confirmed unread (`predict_b39.py`'s `compute()` only ever
indexes `mj['coverage']['counter_writes']`; grep for `interp[` across the
package is zero hits). Nothing verifies this file's sha anywhere in the
codebase, so the derivation is a plain overwrite with no resolver change.
Source sha256 `194542c8cc79d59f107388515cd1566697e665e79132011aa0d366f37f1a6bb2`
(matches `commitment/freeze-code-manifest.json`), derived output sha256
`c941e7c5bad39210bdc263325a6f920cdef479f853c53cb3c25df3941f4d069a`. See
`release/_private/vit_derivation_manifests/derived-b39-map-manifest.json`.

## split16 stage maps (B23-B30, B40-B47)

130 files (`*-lane.npz` + `*-lane.wiring.json` pairs, one pair per split16
launch), migrated by `release/p2-runnable/tools/migrate_split16.py` from the
6 split16 revision directories (r02-l27-l28 through r07-b47) for the 65
stage-chain freeze files those two node ranges actually execute. Not listed
individually here (130 entries) -- the full per-file sha256 census lives in
`data/split16/role-map.json`, generated by the same script and re-verified
by `glassbox_nr/node_executor.py`'s `load_split16_stage()` on every read
(sha mismatch raises `ValueError`, no silent fallback). See
`data/split16/not-packaged-roles.json` for the freeze-index roles that are
historical metadata only and were deliberately not copied (predictor/
comparator/driver/arith/arith2/mapexec2/mlxdlss_*/stage_spec/table_rsq/
table_rcp/input:*/map_json/ptx_interp_c).

Each stage's `contraction` file and its own `freeze/<TAG>-chain-r1.json`
index are migrated alongside the split16 kernel code itself
(`glassbox_nr/kernels/split16_rXX/`), not under `data/maps/` -- they are
per-revision, not shared across revisions the way the lane maps are. Of the
64 contraction files, 48 are `*-no-contraction.json` (byte copies -- `contract`
is `{}`, everything else is counts/hashes) and 16 are `*-sass-contraction.json`
(2a sweep, 2026-09-15: these mixed the one field actually read,
`load_split16_stage()`'s `con["contract"]` -- a small numeric correction
lookup table -- with real disassembly data, `sass_sites`/`ptx_sites` PC+
operand records; **derived**, keeping only `{"contract": ...}`, see
`release/_private/vit_derivation_manifests/derived-split16-contraction-manifest.json`
and `DERIVED_FILES_MAP.json`). `load_split16_stage()`'s resolver now checks
two shas for a derived contraction role: `source_sha256` against the freeze
index's own recorded value (never edited, still matches the committed
original), and `sha256` against the derived bytes actually on disk.

Negative-test verified: corrupting a sandboxed copy of `L25-lane.npz` under
`pkg/runs/_negative_test_sandbox/` (2026-09-14) and, separately, a derived
`L31-sass-contraction.json` plus a tampered `source_sha256` in
`role-map.json` (2026-09-15) all make `load_split16_stage()` raise
`ValueError` instead of silently loading corrupted/inconsistent data;
sandboxes were deleted after each test, never touching the real data.
